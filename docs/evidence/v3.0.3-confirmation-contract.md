## v3.0.2 根因（保留为历史失败）

v3.0.2 正式批次的真实路径是：模型按 Prompt 选择
`create_after_sales_draft` → Runtime 形成 ActionProposal → 用户确认 → Runtime
将 Draft Skill 原样传入 `gateway.commit()` → Gateway 只允许
`commit_after_sales_action` → `commit_skill_not_allowlisted`，系统安全停止且 Java
写入为 0。根因是缺少服务器控制的 Draft-to-Commit 映射，不是模型随机选错。旧 Release
ID、Batch、FAILED Lock、Ledger、报告及提交 `0eb964b` 均保持不变。

| Proposal Skill | 可形成 Proposal | 确认执行 Skill | 真实 Adapter | 缺少 Adapter 时行为 | 副作用 |

| `commit_after_sales_action` | 是（仅内部正式执行） | 自映射 | 是 | 缺字段不进入 `ready_to_commit` | 确认后可能写 Java |

| `request_customer_evidence` | 是草案 | 未配置 | 否 | fail-closed，不进入可提交 | 不写 Java |
| `schedule_follow_up` | 是草案 | 未配置 | 否 | fail-closed，不进入可提交 | 不写 Java |

禁止按字符串后缀猜映射，模型不能指定最终执行 Skill 或幂等键。正式确认参数由 Runtime
构造：`orderFactRef`、`applicationType`、`proposalRef`、可选 `actionRef`，以及绑定
`taskId + proposalId + contentHash + executionSkill` 的 32 位幂等键。Java 重新执行 JWT、
归属、资格、状态机、幂等、事务和最终写入。
