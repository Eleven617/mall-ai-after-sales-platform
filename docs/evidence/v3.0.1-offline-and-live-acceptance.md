# Mall v3.0.1 离线集中修复与现场验收结果

本证据包绑定代码冻结点 `0162c4059c35211852f409a4c3517a87997b4f56`，分支为 `codex/v3.0.1-offline-acceptance`。报告只使用合成账号、合成订单和本地 Compose 服务；旧 `v3.0-deepseek-flash-final` 锁与失败报告保持不变。

## 1. 修复前根因

- 缺少订单引用时，Runtime 让模型先规划，结构化结果可能无法形成有效 `ask_user`，因而安全阻塞但没有稳定澄清问题。
- Skill Catalog 没有把必需输入作为统一契约暴露给 Runtime；恶意或伪造引用的阻断也不够集中。
- Provider/结构化失败的诊断需要元数据化，不能记录原回答、Prompt 或 reasoning。
- 浏览器现场 Runner 的身份配置固定为默认演示账号，无法绑定一次性合成 Fixture。

## 2. 修改文件和设计变化

- `mall-ai-service/app/runtime/task_runtime.py`：在模型规划前按 Skill 的 `required_input_keys` 做通用前置检查，缺订单/商品引用时进入安全等待，不调用无参数 Skill 或写操作。
- `mall-ai-service/app/skills/catalog.py`：为只读订单、物流、库存 Skill 声明必需输入并提供给模型上下文。
- `mall-ai-service/app/runtime/providers.py`、`app/services/llm_service.py`、`app/services/structured_output_gateway.py`、`app/services/trace_service.py`：补齐有限协议修正、失败阶段和不可逆 request-id hash 的白名单诊断，不保存原始内容。
- `mall-ai-service/scripts/run_real_local_showcase.py`：新增真实本地三链路 Runner（Vue → FastAPI → Java/MySQL/Redis/RabbitMQ），只输出脱敏摘要和哈希。
- `mall-ai-service/scripts/run_deepseek_release_batch.py`、`scripts/Run-V3_0_1-DeepSeek-Release.ps1`：新增单一候选批次入口和独立新锁，旧锁不复用、不改写。
- `mall-ai-service/scripts/field_browser_support.py`：支持进程级合成客户身份绑定。
