日期：2026-10-11。状态：本次功能升级已实现、部署到本地 Compose，并完成真实 DeepSeek、浏览器和重启回归。

业务代码提交：`68bd7d138f6d9d9ef4ba9c00093a3d76617b7a7f`；前端安全依赖提交：`f6777049faa55dfcf265d9e77ccd49ffb2ad490a`。最终证据见 [机器事实包](evidence/handoff-upgrade-facts.json) 与 [32 项现场报告](evidence/handoff-upgrade-acceptance-20261011.json)。远程 CI 按实际证据提交的 SHA 核验，不继承历史成功结果。

目标：一次交付客户交接预览/确认、Java 幂等建案与查询、人工处理、异步原因分析与人工修正、统一窗口运营统计、内部改进事项、兼容迁移和验收。

复用现有 Java 人工案件状态机、角色鉴权、事务、Outbox 与 TaskRuntime ActionProposal。不读取原始用户数据、不覆盖未提交改动、不改历史在线证据。

模型可见性：原因分析仅使用白名单分类、服务端状态和计数，不发送原始聊天/联系方式/订单号。客户请求人工的按钮和确认不依赖模型。分析失败不影响人工领取，结果显示为初判而非技术根因。模型成本由既有 Provider 预算约束；真实回归按小范围合成账号执行。

实现覆盖：Java 契约与迁移、Runtime 交接与保护、客户/人工/运营界面、异步分析、保留期与改进审计、回归和文档。

验收范围：无订单转人工、模型不可用按钮入口、疑问句不建案、确认幂等、未知结果查询、跨账号拒绝、原事项写入冻结、人工领取补件结案、分析失败隔离、运营窗口分页一致、人工复核与改进事项审计、保留策略 dry-run。

## 客户与工作台效果

1. 客户仍只需一个对话入口。自然语言请求人工或点击“转人工”后，选择事项/一般咨询、业务类别与可选原因，查看并确认交接卡。订单不是前置条件。
2. 确认前没有人工案件；确认后显示已登记并等待领取。原任务进入 waiting_human，不能再提交或继续自动业务写入。重复确认与查询返回原案件。
3. 人工工作台沿用现有领取、核验、补件、解决、结案状态机。新版背景卡展示交接阶段、已完成步骤/核验依据计数；当前处理人可修正原因，历史初判仍保留。
4. 运营查看 7/30 天、业务/来源/原因过滤后的列表、总数与原因分布；统计使用同一 SQL 过滤器及 UTC 半开区间，页面按上海时间显示。旧诊断记录单独标明历史口径。
5. 改进事项按 OPEN → TRIAGED → IN_PROGRESS → VERIFYING → CLOSED 推进，版本冲突拒绝；关闭必须选择验证结果。不会因代码提交自动宣称效果改善。

## 执行与数据合同

- 客户确认复用版本化 ActionProposal；全部结构化交接字段绑定服务器生成的投影哈希。旧版无上下文交接卡要求重新生成，不再走旧写入路径。
- Java 对成员/请求键唯一，并锁定成员/活动事项范围。案件、投影、审计与既有 Outbox 在同一事务中保存。同请求不同内容冲突，返回未知时只读查询原请求。
- 同一任务的准备、修订、继续、确认和对账共享 Redis 锁；Java 保持最终幂等与归属权威。Mongo 保存的提案通过序列化往返校验。
- 原诊断链只给人工建议，不自动登记；模型提出人工方案也必须经过客户确认。请求、建议、撤回与确认事件分别记录，尚未宣称完整会话分母或总体转人工率。
- 背景采用封闭枚举、服务器阶段与计数，不引入任意原话摘要。业务目标按类别展示；客户原因属于客户陈述，技术根因仍待人工核实。无依据不推断原因。
- 分析采用 Java 持久化待处理记录 + 90 秒租约，后台每 15 秒领取；最多两次领取，单次模型超时 30 秒、输出上限 800 tokens。该投影仅含少量封闭字段，不复制最近聊天。分析服务不用客户 JWT，不能建案或退款；失败不影响领取。输入哈希、分类/提示版本和模型版本留档。
- 清理默认 dry-run；关闭满 90 天的背景投影、超过 365 天的关闭案件事件分批处理（每类每批最多 100），支持保留标记，事务内检查并审计。活跃/重开案件不清理；原订单、聊天和人工案件审计不在清理范围。本轮未执行真实历史数据删除。

第一次现场完成 24 项、4 次模型请求成功、5,809 tokens。后续补齐哈希保护时，Mongo 重读把数字连续的服务器哈希误判为业务标识，导致确认返回 500（Provider 0）；已为服务器专用哈希增加严格格式校验和序列化回归，并保持拒绝模型提供该字段。

## 使用与运维

最终交互复核补齐了一般咨询卡的改原因/过期续期：复用原事项和请求范围生成新提案版本，旧版本失效；结果未知或已经交接的事项不能借此重复提交。两个新增回归、全量 521/521 以及包含卡片修订的 32/32 现场通过；本次真实模型 4 次成功、5,983 tokens。上述五个成功验证范围累计 20 个逻辑请求、21 HTTP attempts、29,080 tokens，各报告独立保留。

访问 `http://127.0.0.1:5173`。客户在聊天页点击“转人工”；售后处理角色在人工工作台领取，运营角色在“人工交接与问题改进”筛选及推进事项。默认本机继续使用已经配置的真实 DeepSeek，密钥与合成账号凭据未提交。

分析可通过 `MALL_HANDOFF_ANALYSIS_ENABLED` 关闭，关闭不影响建案/人工处理。独立执行入口为 `mall-ai-service/scripts/run_handoff_analysis_worker.py --once`。迁移新增表、可重复执行；回退应用时保留数据，不能恢复原诊断的无确认自动登记行为。
