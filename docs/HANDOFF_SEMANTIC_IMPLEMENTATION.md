# 人工交接语义分析实现合同

本版范围：安全上下文预览、确认后模型摘要、本地相似候选、人工主问题组、按需组分析、关联改进与验证证据。第二阶段自动聚类仍是研究路线，不属于本版。

本轮已纳入 `HUMAN_HANDOFF_PHASE1_REWRITE_BRIEF_20261012.md`：单条模型摘要是第一阶段必需能力。客户描述在准备请求中临时处理，新增对话轮次在进入时生成独立安全语义片段；不回读原始历史、不把原有粗分类模板作为完整摘要。

安全片段使用经过审核的业务词汇作完整词法匹配，保留词序、否定、角色和具体条件；未知词句整句排除，疑似敏感输入排除并记录缺失标志。不是用正则宣称任意文本均已脱敏。第一版词汇覆盖有限，因此不支持的表达会保留“内容不足”，不会伪造通用摘要。最多八条、三千字符，并用 UTF-8 字节上界约束输入；没有宣称此上界等于 DeepSeek 的准确 tokenizer 计数。

确认前安全快照仅保存在带 owner/TTL 的 Runtime 提案，客户可以查看。确认后 Java 同事务保存案件、安全输入与摘要任务，立刻返回案件结果。后台通过九十秒租约领取快照，生成目标、处理过程、未解决问题、客户陈述及来源引用；生成内容标为 AI 未复核。结构化摘要通过后才产生本地索引任务。摘要输入版本最多两次模型尝试，人工重试不重置累计预算、不重新建案。

Java 同事务保存确认输入与摘要任务，摘要成功后创建索引工作，继续是身份、权限、版本、分组、统计、审计的权威。Python 通过 HTTP 领取租约，本地 BGE 对称编码；独立 Chroma 仅保存向量和版本标识，不保存摘要。检索先由 Java 限定窗口和主题，最多 5000 条，再精确余弦排序，返回前重新校验 Java 当前版本。

一个案例每个 taxonomy 最多一个主组。加入时明确主问题，其他问题保留在案例描述中，不重复计数。人工拒绝候选不等于删除案例。组变化使旧分析失效。

组分析最多读取五个不同的人工确认样例，默认关闭；授权验收时使用现有 DeepSeek 和用量账本。单条摘要输出上限 1000 tokens，组分析 1200 tokens，均使用专用非思考抽取配置和三十秒传输保护，原 Agent 高思考配置保持原样。首次组分析实验在旧的高思考配置下耗尽 1200 tokens，已保留失败记录；不把这次失败记成质量通过。模型失败不影响分组和人工业务，Schema/引用检查不替代忠实性评估。

改进验证记录组版本、分析引用、验证方式与证据引用；不能只填“通过”。保留策略沿用闭案 90 天/事件 365 天，删除投影即时阻止查询，派生向量和含源内容草案需清理，活跃和 hold 记录保持原策略。

验证分开记录：单元合同、真实本地 Embedding 效果、Java/浏览器现场、真实 DeepSeek。未经实际执行不记为通过。旧发布证据保持原样。

最终摘要配置为 `summary-v2`：目标与具体追问是模型抽取的自然语言；不确定项只允许六类缺口标签，避免模型在缺口说明中扩写身份或业务资料。客户陈述仍标记未经核验。默认无自动聚类、无自动合组，也没有把相似分数变成概率阈值。

开发验证中保留了失败：早期 Java 对 opaque 引用的整串敏感检测、寄回问题的泛化地址误判、摘要遗漏目标/处理步骤、组分析来源混用及不确定项过度扩写。修复后的结果独立归档，旧本机诊断报告没有改成通过。曾将否定句“不能推断系统拒绝”误计为事实断言的评分器已加否定回归测试，原模型输出与重新评分报告分别保留。

最终版本与机器证据见 [语义升级事实包](evidence/handoff-semantic-facts.json)。四个真实模型摘要质量样本是开发合成样本，逐条核对了目标、否定、处理过程、引用和新增事实；不作为大样本或保留集准确率。早期六类模板相似度实验也不代表当前模型摘要的泛化效果。
