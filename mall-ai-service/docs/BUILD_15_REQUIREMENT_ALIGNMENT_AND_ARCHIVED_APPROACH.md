## 现行产品边界

```text
客户消息
  -> 原有意图 / RAG / Java 工具 / 售后工作流
  -> 内部 CustomerServiceResponse 可保留检索上下文和来源供代码测试
  -> CustomerServicePublicResponse 投影
  -> Vue 只展示 answer、必要事实卡和安全操作
```

- 客户 API 不返回 `rag_sources`、`rag_context`、`tool_result`、`intent`、chunk ID 或距离。
- RAG 质量不在每次客户请求时额外跑评测，也不通过独立测试网站展示。
- 固定评测集只在开发、CI 或一个命名 Build 的验收检查点运行。
- 原 RAG 36 条检索案例和 15 条忠实性合同保留；Java JWT、订单归属、RAG 二阶段证据核验、
  用户确认写入、Redis 会话和 LangGraph 诊断图均不因本次撤销而改变。

## 已移除内容

- 客户回复后的第二次 LLM 自然语言润色及其额外成本、延迟和失败回退。
- `/review/login`、`/review/overview`、管理员 JWT 转发和审核角色白名单。
- 审核观察记录、自然表达专属评测、Build 15 专属测试和本机管理员 Docker 依赖。
- 只为上述审核接口新增的 `MALL_ADMIN_API_BASE_URL`、`REVIEWER_ROLE_NAMES` 配置。

`trace_service` 仍保留，因为自定义 ReAct、LangGraph 诊断和售后草稿流程都使用其脱敏日志；
但它不再维护 Build 15 审核接口的内存历史。

## 验收与非目标

本次回退后应验证一条客户政策问答：页面能展示原 RAG 答案，公共响应不泄漏内部字段，
且答案没有额外的 Build 15 过渡语。后端 RAG 评测与公共 DTO 测试作为开发检查点运行。

这不是生产上线、在线 RAG 准确率或模型质量提升声明。下一个新增模块仍须先写清：

1. 用户和数据可见范围；
2. 一条真实验收链路；
3. 明确非目标；
4. 新增模型调用、成本与延迟；
5. 获得确认后才实施。
