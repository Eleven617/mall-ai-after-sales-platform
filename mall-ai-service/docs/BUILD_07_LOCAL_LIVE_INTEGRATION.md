## 现场发现与修复

### 1. 明确业务动作不能只依赖模型分类

现场输入“订单号：… 的耳机损坏，申请退货”曾被模型返回为政策咨询路由，导致只
展示 RAG 答案而未进入草稿。现在 `intent_service.py` 提供一个**窄范围的服务端
路由**：

- 明确查订单/物流：直接进入同一个只读工具契约；
- 明确“申请退货 / 提交退货”：只进入可逆的退货草稿流程；
- “如何申请退货、政策条件”等问法仍交给 RAG；
- 该路由从不直接创建售后单，商品核验、政策证据和“确认”仍不可绕过。

这不是把 AI 删掉：LLM 仍负责产品提示、退货原因、补充说明和自然语言回答；只是
对少量高风险的明确业务动作，把路由契约固化为可测试的服务端规则。

### 2. 向量提供方不可用时，RAG 不能退化为编造

本机 Gemini 代理不可达时，`search_similar()` 会失败。现在 `rag_service.py`：

1. 正常情况仍优先 Chroma + Embedding 向量检索，并按余弦距离阈值拒答；
2. 向量提供方失败时，只从受审阅的本地 Markdown 中做具体政策词证据匹配；
3. “退货”这类泛词不足以成为证据，例如“退货送多少积分”仍返回无证据；
4. 有明确证据时才调用 LLM 基于证据组织回答，否则仍转人工。

这是一条**可用性降级**，不是“已经完成混合检索/Rerank”的简历表述。完整的
关键词 + 向量融合、评测对比和 Rerank 仍在后续计划中。
